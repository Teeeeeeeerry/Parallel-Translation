# 实测：打开 matchOriginAsFallback 之后，重广告页面多注入多少个 frame、整页翻译多发多少请求（#849、#939）

测量日期：2026-10-13。用途：#849 打开了内容脚本的 `matchOriginAsFallback`，sandbox 的 srcdoc、data: 与 blob: 的 iframe 以及不透明来源下的 about:blank 都按父页面的网址注入。本件记下这一选项在重广告页面上的实际代价，作为 #939 拍板“维持现状”的依据。本件不改产品代码。

## 1. 结论

**维持现状（#939 方向 A）。** 选项保持打开，不按 frame 来源或尺寸收窄整页翻译的采集范围。

## 2. 口径

照 #851（`docs/research/page-gate-content-share.md`）的路子，临时脚本放在本机临时目录，没有进仓库：

1. Playwright 自带的 Chromium 无头模式加载扩展，开、不开 `matchOriginAsFallback` 各构建一份（2.1.137 的代码，只差这一个选项）。
2. 同一组首页各跑一遍：载入后等 15 秒让广告位填满，数出各种来源的 frame、其中注入了内容脚本的。
3. 再经 popup 同一条路广播整页翻译，等 20 秒，数引擎替身收到的请求数与原文字符数，以及各 frame 里出了译文的个数。翻译走端到端的替身，不打真实引擎。

## 3. 数据

| 页面 | 不开：注入 frame | 开：注入 frame | 开：其中不透明来源 | 整页翻译请求（不开 / 开） | 原文字符数（不开 / 开） | 新注入 frame 里出了译文的 |
|---|---|---|---|---|---|---|
| cnn.com | 34 | 17 | 9 | 123 / 123 | 6538 / 6538 | 0 |
| forbes.com | 250 | 41 | 16 | 47 / 47 | 2290 / 2290 | 0 |
| weather.com | 139 | 173 | 37 | 191 / 191 | 3364 / 3364 | 0 |
| yahoo.com | 35 | 64 | 18 | 387 / 386 | 10430 / 10394 | 0 |
| foxnews.com | 15 | 21 | 6 | 328 / 328 | 18805 / 18812 | 0 |
| independent.co.uk | 3 | 85 | 5 | 266 / 265 | 10252 / 10229 | 0 |

dailymail.co.uk 拦下了无头浏览器（两次都只有 3 个请求、0 个 frame），不计入。

读法：

- 广告每次轮换，两次加载的 frame 总数差别很大（forbes 一次 250 个、一次 41 个），前两列不能直接相减。
- 能稳定比的是“开：其中不透明来源”一列：这些 frame 只有打开选项之后才会注入，每页 5 到 37 个。
- 实测里它们全是 sandbox 的 about:blank 与 srcdoc 广告位，没有遇到 data: 或 blob: 的 frame。
- 整页翻译的请求数两边差 0 到 1 个，原文字符数差不到 0.5%，这点差异来自两次加载时首页内容本身的变化。
- 新注入的 frame 一个都没有出译文：广告位里没有够长的正文，采集采不到单元。

## 4. 为什么维持现状

- **实测代价是零。** 请求数、原文字符数都在两次加载的自然波动之内，新注入的 frame 没有产出任何翻译单元，不占配额、不多发请求。
- **不选 B（不透明来源的 frame 只给输入翻译用，整页翻译不采）。** 网页邮箱常把邮件正文放在 sandbox frame 里，B 会把它又挡回去，那正是 #849 要补的那一块。等于用一个已测为零的代价，换回一个真实的功能缺失。
- **不选 C（按 frame 尺寸或内容收窄）。** 要再实测一个尺寸阈值，判定还要读布局。这个仓库在页面级闸门的阈值上已经连摔三轮（#843 之后的一串），不值得为一个没有量出来的开销再开一轮。

## 5. 已知未量

- **几十个内容脚本实例的 CPU 与内存没有量。** 每个新注入的 frame 都多跑一份内容脚本（启动、读设置、挂监听），整页翻译时各走一遍采集，输入翻译的圆点也各挂一份监听。
- 本次刻意不量：决定是什么都不做，不需要再花一轮数据来论证不动手。
- 以后真有人报告页面变卡，再按症状去量，量法可以沿用上面的口径，另加每个 frame 的脚本耗时与堆大小。

## 6. 何时重新考虑

- 出现“广告位里的成段文字被整页翻译送翻”的报告：那时采集确实采到了广告位，B 或 C 才有实测收益可言。
- 出现上一节的卡顿报告。
- Firefox 128 起认 `match_origin_as_fallback`，109 到 127 版忽略它。Firefox 上的实际行为本次没有测到（本机端到端跑不了 Firefox 扩展），重新考虑时一并补测。
