**硬串行**：0 → 1 → 2 → 3。设置层 → 能翻 → 翻得全，前一步不完成后一步无意义。

**可并行**：4、5、6 均只依赖 0-3，彼此无耦合。人手不足时按 4 → 5 → 6 顺序（渲染质量优先于交互丰富度）。

**收尾**：7 依赖 1 的 schema 与 6 的快捷键（设置页要展示这两者）；8 最后做。

## 排期原则

两条约束决定了上面的顺序：

1. **数据层先于 UI 层。** settings 与 storage 提到阶段 1，是因为后续每个阶段都要读写设置。若拖到后期，中间阶段只能硬编码默认值，等设置页做完再回头接线 —— 那是确定会发生的返工。
2. **每阶段结束都能装进浏览器看到东西。** 不接受"写了三天但跑不起来"的阶段。阶段 2 结束时就应当能在 Wikipedia 上点出对照译文。

## 文档结构约定

每份阶段文档统一七段式，**上下文自包含** —— 可以只带这一份文档开新会话执行，无需回读其他阶段：

| 段落 | 内容 |
|---|---|
| 目标 | 一句话说清本阶段结束后能做什么 |
| 前置依赖 | 依赖哪些阶段的哪些具体产物 |
| 交付文件清单 | 精确路径 + 每个文件的职责 |
| 关键代码骨架 | 核心接口签名、数据结构、关键函数骨架 |
| 实现要点与取舍 | 为什么这么做、坑在哪 |
| DoD 验收标准 | 可机械判定的完成条件 |
| 验证步骤 | 跑什么命令、开什么页面、看什么现象 |

## 全局要求

这些要求贯穿所有阶段，实现时不要各自发明：

- **命名前缀**：CSS 类、DOM `data-` 属性、storage key 一律用 `pt-` / `pt` 前缀
- **译文 DOM 结构**：`<span class="pt-origin">` + `<span class="pt-trans">`，容器打 `data-pt="done"`
- **模式与样式切换**：类名挂在 `<html>` 上，切换零请求、瞬时生效
- **扩展自身注入的 UI**：宿主元素打 `data-pt-ui="1"`，DOM 遍历时必须跳过
