## 1. 缺陷来源

DoD 第 7 项「鼠标移到段落上浮出按钮，能顺利移动到按钮并点击」在前两轮均判为通过 —— C-5、C-6 两条断言确实覆盖了 200ms 延迟隐藏与"离开段落后移入按钮"的路径。用户实机使用后反馈按钮**根本点不到**，且尺寸偏小。

复查发现自动化用例的盲区在于：它们在 jsdom 里直接派发 `mouseout` 后紧接着派发按钮的 `mouseover`，中间没有真实指针穿越间隙的耗时，也没有真实布局 —— 恰好绕开了两个真正致命的因素。这是 [DoDR-1 §5](DoDR-1.md#5-验收方式与复现) 里已声明的环境限制在具体条目上的兑现，记录在此作为后续用例设计的反面样本。

---

## 2. 缺陷

### P5-5 段落悬停按钮实际点不到（高，DoD 7）

三个原因叠加，任一单独存在都足以让功能不可用。

**其一，200ms 是从「离开段落」起算的硬预算，且中途还会被白白消耗。** `paragraph-btn.ts` 的 `mouseout` 处理器无条件安排隐藏，而按钮定位在段落右边缘外 4px，指针穿越这段间隙时 `mouseover` 打在宿主页面的其它元素上，旧代码在 `closest(DIRECT)` 返回 null 时直接 `return`，**没有 `clearTimeout`**：

```typescript
const el = (e.target as Element)?.closest?.(DIRECT);
if (!el || el.closest('[data-pt-ui="1"]')) return;   // ← 计时器仍在跑
```

于是这 200ms 要同时覆盖"跨过间隙"与"命中按钮"。更糟的是段落**内部**子元素之间的每一次移动都会触发一次 `mouseout`，同样启动倒计时，只是随后的 `mouseover` 命中同一段落才把它清掉 —— 时序上先减后加，稍有抖动就提前隐藏。

**其二，按钮多半根本不在可见区域。** 旧的 `position()` 无条件写 `left = r.right + 4`、`top = r.top`：

```typescript
btn.style.top = `${r.top}px`;
btn.style.left = `${r.right + 4}px`;
```

段落通常撑满内容列宽，全宽布局（X、Medium 正文区、大量博客主题）下 `r.right` 已经接近甚至等于 `innerWidth`，再 +4 即出界；长段落顶部滚出视口时 `r.top` 为负，按钮被丢到视口上方。用户看到的"闪一下就没了"，相当一部分其实是它出现在了屏幕外。

**其三，按钮是 `position: fixed` 而段落随页面滚动**，显示期间滚动一下按钮就与段落错位，旧代码没有任何重定位。

修法：

| 项 | 旧 | 新 |
|---|---|---|
| 隐藏延迟 | 200ms | 500ms（`HIDE_DELAY` 常量） |
| `mouseout` 判据 | 无条件计时 | 读 `relatedTarget`，仍在同一段落内或正移向 `[data-pt-ui="1"]` 时不计时 |
| 定位 | 直接写 `r.right + 4` / `r.top` | 钳制到视口内：右外侧放不下就落到段落右上角内侧，`top` 夹在 `[4, vh - h - 4]` |
| 滚动 | 不处理 | 显示期间监听 `scroll`（capture + passive）与 `resize` 重新贴合 |
| 卸载 | 只 `unmountIsolated` | 同时摘除 document 与 window 上的四个监听器 |

延迟从阶段文档给的 200ms 改到 500ms 是有意偏离：文档把 200ms 作为"给用户从段落移动到按钮的时间"的示例值，真机上偏紧。500ms 在"够得着"与"不黏手"之间取中，且配合 `relatedTarget` 判据后，段落内部移动不再吃掉预算，实际可用时间比字面值更宽裕。

### P5-6 按钮可点击尺寸偏小（中）

`injected.css` 原为 `font-size: 8px` + `padding: 3px 7px`，实测约 20×15px，指针需要瞄准才点得中，与 P5-5 叠加后体感是"要么点不到要么点不中"。

```
font-size   8px  → 12px
padding     3px 7px → 4px 8px
min-width / min-height  新增 24px
letter-spacing / text-transform  移除（单字「译」不需要字距与大小写变换）
```

24px 是可点击目标的常用下限。字号提到 12px 后 `--pt-font-mono` 的字形也更清晰。

段落按钮组由 9 条扩到 15 条，新增 6 条全部针对本轮缺陷：

```

C-6    离开段落后移入按钮，700ms 后仍可见且可点击
C-6b   段落内子元素之间移动（relatedTarget 仍在段落内）不启动倒计时
C-10   段落 right === innerWidth 时，按钮 left 被钳制在 [0, vw - 24]
C-11   段落 top === -800 时，按钮 top ≥ 0
```

## 4. 仍需真机自测

本轮缺陷正说明自动化用例覆盖不到真实指针轨迹与真实布局，修复效果**需要你在浏览器里再确认一次**：

- 在全宽布局站点（X、Medium）上 hover 段落，按钮应出现在可见区域内而非屏幕外
- 从段落边缘沿直线移向按钮，中途停顿约半秒仍应可点
- 段落内有链接、加粗等内联元素时，在其间移动按钮不应闪烁或消失
- 显示期间滚动页面，按钮应跟着段落走
- 按钮大小是否合适 —— 24px 是下限，若仍觉小可再往上调，改 `injected.css` 一处即可
